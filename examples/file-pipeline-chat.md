# 示例对话：文件处理流程

这段对话聊出了 [dev-doc/file-pipeline/](dev-doc/file-pipeline/file-pipeline.md) 里的全部文档。讨论的部分省略了，只留下跟文档有关的话。

## 1. 聊大纲

**你**：我想做一个文件处理流程。用户上传文档，系统转成纯文本，存起来给搜索用。

（来回聊了几轮：支持哪些格式、文件最大多大、分几步、步骤之间怎么连。）

**你**：大纲定了，写进去。

**Claude**：写好了：`dev-doc/file-pipeline/file-pipeline.md`。一共三步：上传、解析、建索引。每一步做完往任务队列里放一条消息，下一步收到再开始。

## 2. 拆出上传

**你**：先聊上传，拆出来。

**Claude**：建好了 `upload/upload.md`。上级指向大纲，开头的介绍先按大纲里讲上传的话写了。大纲最后加了“子模块”，列上了上传。

（聊上传：文件走不走我们的服务器、多大算大文件、传完怎么通知下一步。）

**你**：定了。

**Claude**：`upload.md` 写好了，开头的介绍也改成了“负责把用户的文件存进对象存储。大文件分片传，断了能接着传。”大纲“子模块”里那条也得改成一样的，要改吗？

**你**：改。

**Claude**：改好了。没有别的文档依赖上传，不用再改别的。

## 3. 再往下拆一层

**你**：分片那块细节挺多，单独拆出来。

**Claude**：建好了 `upload/chunking/chunking.md`，上级是上传。上传里讲分片的两句细节搬了过去，上传的“子模块”里只留了一句介绍。

（聊分片：每片多大、失败了怎么重试、断点续传记在哪。）

**你**：定了。

**Claude**：`chunking.md` 写好了。开头的介绍还准，跟上传“子模块”里那条一样，不用改别的。

## 4. 拆出解析

**你**：接着聊解析，拆出来。它要用上传发出的那条消息。

**Claude**：建好了 `parse/parse.md`。上级是大纲，依赖写了上传，开头的介绍先按大纲写了。大纲的“子模块”里，解析排在上传后面，跟正文的顺序一样。

（聊解析：三种格式各怎么转、扫描版 PDF 怎么办、失败了怎么办。）

**你**：定了。

**Claude**：`parse.md` 写好了。开头的介绍还准，不用改别的。

## 5. 换个对话，回头改上传

（第二天，新开了一个对话。）

**你**：继续聊上传完成后发的那条消息。

**Claude**：先读了大纲和 `upload.md`。现在这条消息里有文件 ID、文件名、格式和存储路径。想改哪里？

**你**：消息里只放文件 ID 就行，别的让下一步自己去查。定了。

**Claude**：`upload.md` 改好了。`parse.md` 依赖这条消息，它的第 1 条得跟着改：收到消息后，先用文件 ID 查出文件名、格式和存储路径，再开始解析。要改吗？

**你**：改。

**Claude**：`parse.md` 改好了。大纲不受影响。
